# 법률 문서 개발 v1 — 2026-09-30.r1

## 현재 확정 상태

사용자 승인에 따라 이용약관, 개인정보 처리방침 및 수집·이용 안내, 이메일 마케팅, SMS 마케팅 네 문서를 `active`로 확정했습니다. 버전은 모두 `2026-09-30.r1`, 시행일은 `2026-09-30`입니다. 현재 구현된 회원가입·회원정보·주소록 범위의 첫 공개 개발 버전이며, 운영 배포·주문·광고 발송 준비 완료를 뜻하지 않습니다.

이름·이메일·비밀번호 필수, 전화번호 선택을 유지합니다. 이용약관·개인정보 수집·이용은 필수, 이메일·SMS 마케팅은 각각 선택입니다. 선택 미동의도 `false`와 해당 문서 버전으로 기록합니다. `signup-consents.ts`의 가입 당시 버전 스냅샷·암호화 쿠키·서명된 RPC 저장 구조는 변경하지 않았습니다. draft 차단과 오래된 버전 거부 안전장치는 유지하되, 현재 네 문서가 활성 상태이므로 가입할 수 있습니다.

사업자·배송/반품 정책과 법정 보존기간은 기존 확정 내용을 유지합니다. 개인정보 문의 담당은 대표 임성준, 고객센터 010-2079-9282 / omjm1000@naver.com으로 정리했습니다. Vercel이 이미 운영 중이라는 표현은 운영 배포 준비 중으로 수정했습니다.

서울 Supabase 이전, migration 4개 적용, 앱/DB 서명키 일치, 전화 암호화키 및 localhost URL 설정 완료는 사용자가 확인한 상태를 기준으로 합니다. 이번 작업에서 원격 DB나 Sydney 프로젝트에 접속·변경하지 않습니다. migration·DB schema·Vercel·SMTP·주문/결제 기능은 변경하지 않습니다.

## 후속 운영 체크리스트

다음 항목은 개발 v1 회원가입을 차단하지 않으며 해당 기능의 실제 운영 전에 확인합니다.

- [ ] 실제 물류업체명·계약·재위탁·전달 항목·기간과 위탁/제3자 제공 관계를 확인하고 공개한다. 상품별 배송/반품 비용과 회수지도 갱신한다.
- [ ] 실제 PG사를 선택한 후 주문/결제 단계의 수집 항목·근거·보유기간·수탁/제공 관계를 안내한다.
- [ ] Vercel 운영 배포의 리전·계약·로그·쿠키·분석 설정 및 운영 URL을 확인한다.
- [ ] Production Custom SMTP 제공자·발신자·한도·국가·보유기간을 확인하고 인증 이메일을 검증한다.
- [ ] 마케팅 철회 UI와 수동 처리 절차, 무료 수신거부, 발송 직전 최신 동의 확인, 처리 결과 안내·정기 확인을 준비한다. 현재는 선택 기록만 저장하며 광고를 발송하지 않는다.
- [ ] 실제 주문 데이터의 분리보관/파기를 구현한다. 계정 삭제 cascade 전에 법정 보존 대상 여부를 확인한다. 주문이 없어도 실제 발생한 민원·광고 기록의 보존 의무는 별도로 판단한다.
- [ ] Supabase 서울 리전 외 백업·지원 접근·재수탁자·인증 메일의 국가, 계약 법인·연락처·로그/백업 보유기간과 국외 이전 근거·고지를 보완한다. 국내 리전만으로 국외 이전이 없다고 단정하지 않는다.
- [ ] 이름 필수 수집의 최소 필요성과 선택 전화번호 처리 근거·별도 동의 필요성을 확인한다. 전화번호 입력을 SMS 마케팅 동의로 취급하지 않는다.
- [ ] 만 14세 미만 가입 정책과 연령 확인/법정대리인 동의 절차를 확정한다. 현재 기능이 없다는 사실을 본문에 명시했으며, 개발 v1 활성화가 이 누락의 해결을 뜻하지 않는다. [개인정보 보호법 제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523)
- [ ] 대표자의 개인정보 보호책임자 지정 요건과 권한, 요청 본인 확인·처리 기록·탈퇴·백업 파기 절차를 점검한다. 문의 담당 확정과 법정 지정 요건 검토 완료를 구분한다.
- [ ] Kakao 주소 검색의 외부 처리와 인증 로그/세션 유지 기간을 확인한다. 동의 증빙의 추가 보존은 구체적 근거·기산점·최소 항목을 정하며 임의로 일괄 5년을 적용하지 않는다.

특히 아동 가입 처리, 선택 전화번호 처리 근거, 현재 사용하는 Supabase의 위탁/국외 이전 상세 고지는 실제 개인정보 운영에 영향을 주는 미확정 사항입니다. 이를 법률 검토 완료로 표시하거나 누락이 없다고 단정하지 않습니다. 이후 문서를 바꿀 때에는 이번 본문을 Git 이력에 보존하고 새 revision을 발급합니다.

## 직접 수행할 회원가입 E2E

1. `pnpm dev` 실행 후 `http://localhost:3000/signup`을 새로고침하고 약관 링크의 버전/시행일을 확인한다.
2. 본인이 수신 가능한 이메일과 이름·비밀번호를 입력한다. 전화번호는 비우고 필수 두 항목만 선택하여 가입 요청한다. 테스트용 계정은 운영자가 직접 생성한다.
3. 가입한 브라우저·프로필에서 1시간 이내 이메일 인증 링크를 연다. 임시 쿠키를 지우거나 다른 브라우저로 전환하지 않는다. 메일이 오지 않으면 현 인증 발송 설정의 허용 주소·한도와 스팸함을 확인한다.
4. 가입 완료·로그인·마이페이지 이름과 전화번호 공란을 확인한다. 동의 저장 경고가 있으면 복구 안내에 따라 재시도하고 계속 실패하면 로그의 오류 코드만 확인한다.
5. **Seoul** Supabase에서 해당 Auth 사용자 ID로 `member_consents`를 조회한다. `signup_record=true`인 네 행의 `document_version`은 모두 `2026-09-30.r1`, `terms/privacy`의 `granted=true`, `marketing_email/marketing_sms`는 `false`여야 한다. 접수/기록 시각과 사용자 ID도 확인한다.
6. 선택 동의 실제 저장까지 검증하려면 운영자가 별도로 허용한 이메일로 이메일/SMS 선택 조합을 바꿔 반복한다. 전화번호 없이 SMS 동의를 선택해도 가입 가능해야 한다. 선택 조합 네 가지는 자동 테스트에서도 검증한다.

## 결론

제공된 사업자·배송·취소·반품 정책을 `lib/legal/documents.ts`에 반영했습니다. 이용약관, 개인정보 처리방침/필수 수집·이용 안내, 이메일 마케팅, SMS 마케팅의 네 문서입니다. 사업자번호는 제공된 1160638730을 읽기 쉽게 116-06-38730으로 표시했습니다. 공식 등록 사실을 별도로 조회·인증한 것은 아닙니다.

버전 후보는 **2026-09-29.r1**입니다. 아래 미확정 사항 때문에 네 문서 모두 `draft`, `version=null`, `effectiveDate=null`을 유지합니다. 현재 가입 차단을 해제할 수 없습니다. 승인·실제 시행이 뒤로 미뤄지면 그 날짜에 맞는 버전을 검토하고 소급하여 동의를 받은 것처럼 표시하지 않습니다.

2026-09-30에는 가입 이름 필수·전화번호 선택 입력과 쿠키/인증 완료 처리를 수정했습니다. 동의 저장 프로토콜, RLS 및 원격 DB는 변경하지 않았습니다. `20260929020000_signup_consent_records.sql`도 수정하지 않았습니다. 이번 작업은 해당 migration의 원격 적용 여부나 서명키 설정 완료를 확인하는 작업이 아닙니다.

### 가입과 주문 정보의 구분

기존 구현에는 이름 입력이 없었습니다. 요청 정책에 따라 가입 이름을 필수로 추가하고 이메일·비밀번호를 유지했습니다. 전화번호는 선택으로 바꾸었습니다. 이름 필수 수집의 최소 필요성/법적 근거와 선택 연락처 수집 근거·별도 동의 필요성은 `[확정 필요]`입니다. 개발상 필수 여부가 법적 필수 수집 근거가 되는 것은 아닙니다.

`profiles.phone`은 원래 nullable이므로 migration이 필요 없습니다. 이름은 Auth metadata → 인증된 사용자 확인 → 비어 있는 `profiles.display_name`에 저장합니다. 실패 시 인증을 취소하지 않고 기존 마이페이지에서 보완할 수 있습니다. 이름 metadata는 이후 프로필 변경과 자동 동기화되지 않는 가입 당시 데이터이므로 탈퇴 시 Auth 데이터도 삭제 범위에 포함해야 합니다.

현재 주소록은 구현되어 있지만 `/order`는 준비 화면입니다. 향후 주문은 수령인·배송 연락처·배송 주소를 필수로 받되 회원 연락처와 별도로 주문 당시 정보를 저장할 예정입니다. 회원 번호는 기본값으로만 사용할 수 있고 다른 수령인 번호를 허용해야 합니다. 주문 DB·결제·배송 전달 기능은 이번에 만들지 않았습니다.

- 그루잠 지시에 따라 주문 배송·설치만 수행하고 자체 목적으로 이용하지 않는 구조라면 처리위탁으로 검토합니다. 목적 제한·보호조치 등을 문서화하고 수탁자 교육·감독 및 재위탁 동의가 필요합니다. 위탁업무와 실제 수탁자(재수탁자 포함)를 쉽게 확인하도록 공개해야 합니다. 업체가 매번 바뀌어도 단순히 “외부 물류업체”만 표시하고 완료할 수는 없습니다. [개인정보 보호법 제26조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0026&lsiSeq=283839&urlMode=lsScJoRltInfoR)
- 업체가 독자적인 목적·이익으로 활용하는 관계라면 제3자 제공 해당 여부와 제17조상 근거를 별도로 검토합니다. 계약명만으로 분류하지 않습니다. `[확정 필요]` 실제 계약, 지시·감독 범위, 자체 이용 여부, 재위탁 업체, 삭제 시점.

- 전달 예정 범위는 수령인·배송 연락처·주소·필요 최소 상품/설치 정보입니다. 계정 비밀번호·회원 동의 이력·다른 주소록은 전달 대상이 아닙니다. 업체명·보유기간을 만들어 넣지 않았습니다.

현행 시행령 제28조는 위탁업무·수탁자를 인터넷 홈페이지에 지속적으로 게재하는 공개 방법을 정하고 있습니다. 처리방침 또는 연결된 상세 목록이 실제로 계속 접근 가능한지 확인해야 합니다. [시행령 제28조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0028&lsiSeq=289537&urlMode=lsScJoRltInfoR)

### Supabase

코드에서 확인한 사용 범위는 Auth(이메일/비밀번호, PKCE, 세션, 가입 이름 metadata), PostgreSQL의 profiles/addresses/member_consents 및 동의 RPC입니다. 서비스 전체 기능 목록을 그루잠 사용 기능으로 간주하지 않습니다. Storage/Edge Functions/AI 기능을 회원 데이터 처리 서비스로 추가하지 않았습니다.

공식 문서상 프로젝트는 기본 리전 하나에 배포되며 선택 리전은 주요 데이터 저장 위치에 영향을 줍니다. 서울도 선택지지만 코드만으로 이 프로젝트가 서울인지 알 수 없습니다. 일반 APAC 선택을 한국 저장으로 해석하면 안 됩니다. [리전 문서](https://supabase.com/docs/guides/platform/regions)

[DPA](https://supabase.com/legal/customer-resources/data-processing-addendum), [하위처리자 목록](https://supabase.com/legal/subprocessor-list/June-1-2026.pdf)

### Vercel

운영자가 Vercel 사용을 명시했습니다. 코드상 가입 Action은 이름·이메일·비밀번호·선택 전화·동의값을 받고, callback/SSR/proxy는 인증 코드·쿠키·회원 식별정보를 처리합니다. 프로필·주소록 서버 요청/응답도 호스팅을 거칩니다. 브라우저 로그인은 Supabase에 직접 요청하지만 세션 쿠키는 후속 서버 요청에 포함됩니다. 따라서 Vercel을 정적 파일만 제공하는 업체로 적을 수 없습니다. 이는 코드 흐름에 따른 판단이고 실제 로그에 요청 본문이 저장된다는 뜻은 아닙니다.

Functions의 문서상 새 프로젝트 기본 리전은 미국 iad1이며 Dashboard에서 변경할 수 있습니다. CDN 및 Routing Middleware 지역은 Functions 설정과 다를 수 있습니다. 이 프로젝트의 실제 배포 리전은 `[확정 필요]`입니다. [Functions 리전](https://vercel.com/docs/functions/configuring-functions/region)

DPA는 Pro/Enterprise 고객의 processor 처리에 대한 적용 범위를 명시하고 하위처리자 목록을 Trust Center로 연결합니다. 그루잠의 플랜·계약에 자동 적용된다고 가정하지 않습니다. `[확정 필요]` 계약 법인, 플랜/DPA, 실제 하위처리자·국가, 로그/백업/지원 접근·보유기간, Drains/외부 관측 연결 및 Analytics 활성 여부. 앱 의존성에서 별도 Vercel Analytics SDK는 발견하지 못했지만 Dashboard 기능 부재를 증명하지는 않습니다. [Vercel DPA](https://vercel.com/legal/dpa), [Trust Center](https://security.vercel.com/)

[현행 제28조의8](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=08&joNo=0028&lsiSeq=283839&urlMode=lsScJoRltInfoR)
